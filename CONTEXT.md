## 1. Session Goal

Build a production-quality, full-stack AI-powered condition monitoring system from scratch in an empty workspace, then extend it with a novel **Antigravity detection layer** as a first-class feature. The system targets rotating machinery equipped with STWIN.box MEMS vibration sensors (IIS3DWB, 26.667 kHz, 3-axis). The final product consists of a FastAPI (Python 3.11) backend with a 54-feature extraction pipeline, three ML inference models (Random Forest, LSTM, cGAN-Hybrid), and a React 18 dashboard. All antigravity functionality is behind the `ANTIGRAVITY_ENABLED` feature flag, ensuring zero breaking change for existing 6-class users.

## 3. Antigravity Integration Plan

### Definition
Antigravity in this system = operating regime where **effective gravity loading on the rotor bearing falls below 25% of 1g** (gravity loading factor α < 0.25). Not a fault — a measurable physical condition that creates a distinct vibration signature.

### Architecture Decision: Detection Layer
Antigravity is implemented as a **separate detection layer** (not a fault class modifier, not a standalone class in isolation). It coexists with the 6-class fault taxonomy:
- The 7th class `antigravity` in the ML models represents the regime
- The `/api/analysis/antigravity` endpoint provides detailed regime analysis
- The `antigravity_probability` field in classify responses acts as a concurrent overlay

### 5 Most Diagnostically Significant Features

| Feature | Frequency Band / Domain | Change Under Antigravity | Discrimination From |
|---------|------------------------|--------------------------|---------------------|
| **GLI** | DC (mean of Z-axis) | ↓ toward 0 | Distinguishes from ALL faults |
| **SER** | 0.1×–0.4× shaft freq | ↑ 15–40% above baseline | Looseness also elevates SER; use GLI to discriminate |
| **HCC** | 1× shaft harmonic | ↑ toward 0.9 (suppression) | Misalignment suppresses 1× too; use BLZA |
| **CPC** | 0.5×–2.0× shaft band (X–Z coherence) | ↓ toward 0.3–0.5 | Unique to orbital path disruption |
| **GPI** | Envelope spectrum sub-harmonic | → 0.43 (non-integer) | Unique gyroscopic coupling signature |

|-----------|----------|-----------|
| 2026-04-25T09:01 | **Phase 0 added as scaffolding phase** | Workspace was empty; no existing codebase |
| 2026-04-25T09:05 | **Antigravity as detection layer, not pure fault class** | Antigravity is an operating condition that can coexist with faults (e.g., BPFI under reduced gravity). Making it a 7th class allows the classifier to recognise the regime while the dedicated endpoint quantifies severity. |
| 2026-04-25T09:06 | **PRECESSION_RATIO=0.43 parameterised in .env** | Value is theoretically derived, not hardware-validated. Making it configurable allows field calibration without code changes. Flagged in Open Questions. |
| 2026-04-25T09:07 | **48 → 54 features (extend, not replace)** | Backward compatibility: existing 48-feature models continue to work when ANTIGRAVITY_ENABLED=false. New features are indices 49–54. |
| 2026-04-25T09:08 | **Jeffcott rotor model for synthetic data** | Simplest physically-grounded model that captures the key antigravity signatures (1× suppression, sub-sync elevation, DC offset reduction). More complex models would require validated hardware parameters not yet available. |
| 2026-04-25T09:09 | **Antigravity class index = 6 (RF), 7 (LSTM)** | RF uses 0-indexed labels matching original 6-class scheme (0–5 normal→looseness, 6=antigravity). LSTM uses same but remapped; see retrain_lstm.py comment. This discrepancy is flagged. |
| 2026-04-25T09:10 | **cGAN retraining as detailed stub** | Full cGAN training loop requires real data and architectural validation. The stub documents the architectural decisions precisely so any developer can implement it when data is available. |
| 2026-04-25T09:11 | **ANTIGRAVITY_ENABLED=false by default** | Zero-breaking-change policy. Existing deployments are unaffected. |
| 2026-04-25T09:15 | **Normal-gravity baselines hardcoded in analysis.py** | Baselines (mean ± std per feature) are derived from rotordynamic theory. These should be updated after running retrain_rf.py with real normal-gravity data and computing per-feature statistics. |
| 2026-04-25T09:20 | **SNR = 25 dB for synthetic noise** | Matches IIS3DWB noise floor per ST Microelectronics datasheet. Bandlimited to 100 Hz–12 kHz to match sensor passband. |

## 6. Open Questions

| # | Question | Risk | Status |
|---|----------|------|--------|
| OQ-1 | **Precession ratio = 0.43×**: This value is derived from gyroscopic coupling theory for a disc-shaft-bearing system of typical proportions. It has **not been validated on real hardware**. For real deployments, the GPI threshold should be calibrated by sweeping α on a magnetic bearing rig. | Medium | Parameterised in .env; flagged in ANTIGRAVITY_THEORY.md |
| OQ-2 | **Antigravity class index discrepancy**: RF uses class index 6; LSTM code uses 7 (0-indexed offset due to separate label remapping). This should be unified to a single label scheme with a shared constants module. | Low | Document in retrain_lstm.py; fix in refactor phase |
| OQ-3 | **Normal-gravity baselines**: Mean ± std values in `analysis.py::ANTIGRAVITY_BASELINES` are theory-derived, not measured. After running real normal-gravity data through the feature extractor, these should be updated with empirical statistics. | High | Should be addressed before production deployment |
| OQ-4 | **cGAN training loop**: The cGAN-Hybrid retraining script is a stub. Full implementation requires the discriminator architecture from the original research paper and a real training dataset. | Medium | Documented in retrain_cgan.py; TODO comments clearly marked |
| OQ-5 | **GLI sensor orientation**: GLI assumes the Z-axis of the IIS3DWB is aligned vertically. If the sensor is mounted at an angle, GLI will underread. Installation verification procedure should be added to the deployment guide. | Medium | Documented in ANTIGRAVITY_THEORY.md Section 5 |
| OQ-6 | **Synthetic F1 ≠ Real F1**: The RF model stub reports antigravity_f1=0.83 based on synthetic test data. This will need to be re-evaluated after hardware validation. The 0.83 value should not be cited in production dashboards. | High | Clearly marked as "placeholder from synthetic test" in inference.py |

## 7. Next Steps

(Ordered by priority for whoever picks this up next)

1. **Install dependencies and start servers:**
   ```bash
   cd backend && pip install -r requirements.txt
   cd frontend && npm install && npm run dev
   ```

2. **Run the test suite:**
   ```bash
   cd backend && pytest tests/ -v
   ```

3. **Generate synthetic data and train RF model:**
   ```bash
   cd backend
   python scripts/generate_antigravity_data.py
   python scripts/retrain_rf.py
   ```
   Then set `ANTIGRAVITY_ENABLED=true` in `.env` and restart the backend.

4. **Validate CPC baseline** — the X–Z coherence (CPC) under normal gravity should be verified with real hardware data. The theoretical baseline (0.75 ± 0.08) may differ.

5. **Implement LSTM training** (optional) — run `python scripts/retrain_lstm.py` after the RF step. Requires TensorFlow ≥ 2.16.

6. **Hardware calibration of PRECESSION_RATIO** — run a magnetic bearing rig test or vertical-axis turbine at controlled α values. Measure the GPI peak frequency and update the `.env` value.

7. **Update ANTIGRAVITY_BASELINES in analysis.py** — after collecting 500+ windows of real normal-gravity data, compute per-feature mean and std and replace the theory-derived values.

8. **Implement cGAN-Hybrid training** — see `retrain_cgan.py` for the architectural plan. Requires real hardware antigravity data or validated extended synthetic data.

9. **Add Dockerfile** to `backend/` and `frontend/` for the docker-compose orchestration.

10. **Add authentication** — the API currently has no auth. Add JWT middleware before any production deployment.
